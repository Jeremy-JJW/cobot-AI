阶段 3 Web 交互界面说明

一、整体定位

1. 界面风格希望像 Codex / ChatGPT 那样简单、干净，以“对话”为主，不做复杂工业软件面板。
2. 用户只需要看到一个自然语言输入框、对话记录、当前状态和必要的安全操作按钮。
3. 页面要适合现场演示：少文字、反馈明确、按钮清楚、视觉上有科技感但不要花哨。
4. 客户界面不出现 OpenClaw 品牌，也不展示底层 Python 控制细节。

二、页面布局

1. 顶部区域
   - 左侧显示系统名称，例如：“COBOT AI 自然语言控臂系统”。
   - 右侧显示连接状态，例如：“未连接 / 已连接 / 执行中 / 已急停”。
   - 连接状态用颜色区分：
     - 灰色：未连接
     - 绿色：已就绪
     - 蓝色：分析中 / 规划中
     - 橙色：执行中
     - 红色：错误 / 急停

2. 主体区域
   - 中间是对话记录区。
   - 用户输入显示为右侧气泡。
   - 系统反馈显示为左侧气泡。
   - 系统反馈要简洁，不要直接堆大段 JSON。
   - 每条记录可以显示一个小标签：规则解析 / 模型解析 / 经验库命中。

3. 底部输入区
   - 一个自然语言输入框，提示语例如：“请输入机械臂动作，例如：抬高 20 毫米”。
   - 一个“发送 / 分析”按钮。
   - 一个“确认执行”按钮：只有解析成功后才可点击。
   - 一个醒目的“停止 / 急停”按钮，始终可见。

三、核心交互流程

1. 用户输入自然语言指令。
2. 系统先显示“正在理解你的指令...”。
3. 如果命中经验库，显示“已从经验库找到相似动作”。
4. 如果走规则解析，显示“已用规则识别动作”。
5. 如果调用 LLM，显示“模型分析中”。
6. 解析成功后，不立刻执行真机，而是显示动作摘要，并等待用户点击“确认执行”。
7. 用户点击“确认执行”后，系统才控制机械臂运动。
8. 执行过程中显示“正在操作机器人运动”。
9. 执行完成后显示“动作已完成”。
10. 如果失败，显示简短可读的错误原因。

四、反馈文案要求

反馈只需要说明当前状态和必要动作，不要太啰嗦。

1. 正在调用 API 或 LLM 语义分析时：
   - “模型分析中”
   - “正在理解你的指令”


4. 已经得到完整 JSON / 动作计划时：
   - “已明白你想要的动作：向 Z 正方向移动 50 毫米，速度 40%”
   - “请确认是否执行”

5. 控制机器人动作时：
   - “正在操作机器人运动”
   - “机械臂执行中，请保持安全距离”

6. 执行完成时：
   - “动作已完成”
   - “机械臂已完成本次动作”

7. 出错或拒绝执行时：
   - “无法执行：移动距离超过安全上限”
   - “无法识别该动作，请换一种说法”
   - “当前能力暂不支持抓取、视觉识别或任意坐标运动”

五、动作摘要显示要求

解析成功后，页面不直接展示完整 JSON，默认展示简洁摘要：

1. 相对移动：
   - “动作：向 Z 正方向移动 50 毫米”
   - “速度：40%”

2. 去命名点：
   - “动作：移动到 A 点”
   - “方式：关节运动”

3. 复合轨迹：
   - “动作：绘制圆形轨迹”
   - “半径：20 毫米”
   - “平面：XY”

4. 调速：
   - “动作：设置速度为 30%”

5. 停止 / 下使能：
   - “动作：停止机械臂”
   - “动作：关闭机械臂使能”

完整 JSON 可以放在“展开详情”里，默认折叠，方便调试但不干扰演示。

六、视觉风格建议

1. 整体采用浅色或深色科技风均可，建议优先做深色演示风：
   - 背景：深蓝黑 / 深灰
   - 卡片：半透明深色
   - 主色：蓝色或青色
   - 成功：绿色
   - 警告：橙色
   - 危险：红色

2. 页面要留白充足，按钮不要太密。
3. 字体要清晰，适合投影展示。
4. 输入框和按钮要大一些，方便现场操作。
5. 对话气泡可以有轻微圆角和阴影，让界面更现代。
6. 状态变化可以加轻微动画，例如“模型分析中...”的小点闪烁，但不要复杂。

七、安全交互要求

1. “确认执行”必须和“分析/发送”分开，不能用户一输入就直接真机动作。
2. “停止 / 急停”按钮始终固定在页面明显位置。
3. 真机执行中禁用普通输入和确认按钮，避免重复发送。
4. 执行中要显示安全提示：“机械臂执行中，请保持安全距离”。
5. 解析失败、参数越界、未注册 Skill 时，不允许出现确认执行按钮。
6. 速度、距离、等待时间等参数仍以后端 `executor.py` 校验为准，前端只负责展示。

八、建议保留的调试信息

调试信息默认折叠，点击“查看详情”后显示：

1. 解析来源：cache / rule / llm。
2. Skill 名称。
3. 参数 JSON。
4. 最近一次计划文件：`generated/last_plan.json`。
5. 错误详情。

九、第一版界面优先级

第一版只做最小可演示功能：

1. 对话式输入和输出。
2. `/api/plan`：只解析，不执行。
3. `/api/run-once`：确认后执行。
4. 急停按钮。
5. 状态反馈。
6. 错误提示。
7. 简洁美观的单页界面。

暂时不做：

1. 登录系统。
2. 多机器人管理。
3. 复杂轨迹可视化。
4. 历史任务数据库。
5. 复杂权限管理。
